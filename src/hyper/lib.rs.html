9//! # hyper
10//!
11//! hyper is a **fast** and **correct** HTTP implementation written in and for Rust.
12//!
13//! ## Features
14//!
15//! - HTTP/1 and HTTP/2
16//! - Asynchronous design
17//! - Leading in performance
18//! - Tested and **correct**
19//! - Extensive production use
20//! - [Client](client/index.html) and [Server](server/index.html) APIs
21//!
22//! If just starting out, **check out the [Guides](https://hyper.rs/guides/1/)
23//! first.**
24//!
25//! ## "Low-level"
26//!
27//! hyper is a lower-level HTTP library, meant to be a building block
28//! for libraries and applications.
29//!
30//! If looking for just a convenient HTTP client, consider the
31//! [reqwest](https://crates.io/crates/reqwest) crate.
32//!
33//! # Cancel safety
34//!
35//! Futures returned by hyper are cancel safe: dropping a future before it
36//! completes is the supported way to cancel the operation. The protocol in
37//! use changes what that cancellation actually does on the wire:
38//!
39//! - **HTTP/1** has no in-protocol way to abort a single request without
40//!   affecting the shared connection, so dropping an in-flight request future
41//!   closes the underlying TCP connection. Any subsequent call on the same
42//!   `SendRequest` returns a `canceled` error; the connection cannot be
43//!   reused.
44//! - **HTTP/2** resets the single stream with `RST_STREAM` (`CANCEL` error
45//!   code) and notifies the peer immediately rather than continuing to
46//!   deliver a response body that would be discarded. The shared connection
47//!   stays usable for other in-flight and future requests.
48//!
49//! See the documentation on individual futures — for example
50//! `SendRequest::send_request` in `client::conn::http1` and the equivalent
51//! in `client::conn::http2` — for the protocol-specific behavior on
52//! cancellation.
53//!
54//! # Optional Features
55//!
56//! hyper uses a set of [feature flags] to reduce the amount of compiled code.
57//! It is possible to just enable certain features over others. By default,
58//! hyper does not enable any features but allows one to enable a subset for
59//! their use case. Below is a list of the available feature flags. You may
60//! also notice above each function, struct and trait there is listed one or
61//! more feature flags that are required for that item to be used.
62//!
63//! If you are new to hyper it is possible to enable the `full` feature flag
64//! which will enable all public APIs. Beware though that this will pull in
65//! many extra dependencies that you may not need.
66//!
67//! The following optional features are available:
68//!
69//! - `http1`: Enables HTTP/1 support.
70//! - `http2`: Enables HTTP/2 support.
71//! - `client`: Enables the HTTP `client`.
72//! - `server`: Enables the HTTP `server`.
73//!
74//! [feature flags]: https://doc.rust-lang.org/cargo/reference/manifest.html#the-features-section
75//!
76//! ## Unstable Features
77//!
78//! hyper includes a set of unstable optional features that can be enabled through the use of a
79//! feature flag and a [configuration flag].
80//!
81//! The following is a list of feature flags and their corresponding `RUSTFLAG`:
82//!
83//! - `ffi`: Enables C API for hyper `hyper_unstable_ffi`.
84//! - `tracing`: Enables debug logging with `hyper_unstable_tracing`.
85//!
86//! For example:
87//!
88//! ```notrust
89//! RUSTFLAGS="--cfg hyper_unstable_tracing" cargo build
90//! ```
91//!
92//! [configuration flag]: https://doc.rust-lang.org/reference/conditional-compilation.html
93//!
94//! # Stability
95//!
96//! It's worth talking a bit about the stability of hyper. hyper's API follows
97//! [SemVer](https://semver.org). Breaking changes will only be introduced in
98//! major versions, if ever. New additions to the API, such as new types,
99//! methods, or traits will only be added in minor versions.
100//!
101//! Some parts of hyper are documented as NOT being part of the stable API. The
102//! following is a brief list, you can read more about each one in the relevant
103//! part of the documentation.
104//!
105//! - Downcasting error types from `Error::source()` is not considered stable.
106//! - Private dependencies use of global variables is not considered stable.
107//!   So, if a dependency uses `log` or `tracing`, hyper doesn't promise it
108//!   will continue to do so.
109//! - Behavior from default options is not stable. hyper reserves the right to
110//!   add new options that are enabled by default which might alter the
111//!   behavior, for the purposes of protection. It is also possible to _change_
112//!   what the default options are set to, also in efforts to protect the
113//!   most people possible.
